The benches

Thirty seconds each. Break them if you can.

01

An LLM step returns a string, not a contract

Nine hostile model outputs fired at a real validation node. Seven get held for a human with a named reason. Two are supposed to pass. Nothing reaches the destination in a shape it cannot handle.

Proves
Shape validation on an AI step catches the malformed outputs that otherwise write nonsense into a CRM.
Does not
Prompt injection inside a valid field is still a well-shaped string, and an allowlist has no opinion about a confidently wrong category.

 02

Two endpoints checked the caller, one did not

An agent tries the guarded calls, gets 403 twice, then finds the one that never asks whose reservation it is. Somebody loses their place so a stranger gains one.

Proves
Authorization on most of your endpoints is authorization on none of them.
Does not
One check on one endpoint is not an audit, and nothing here stops a compromised session.

Run it →

 03

The price is in the URL, so it is not yours

Edit the price in a prefilled payment link and authorize it. A $450 job gets paid at $50, with a genuine signature on file and nothing on the office screen that looks wrong.

Proves
Hidden and read-only are properties of a browser, not of your money. Build the charge server side.
Does not
Server-side pricing fixes the number and nothing else about who may open the job or replay the link.

Run it →

 04

The run was green and three orders were gone

Twenty orders, one flaky API, and the only thing that changes is the error setting on one node. The setting most people land on writes twenty rows, reports success, and loses three orders without telling anyone.

Proves
A workflow that reports success is not a workflow that delivered your data, and retrying is not the same as handling.
Does not
It models three settings on one node. Credential expiry, partial writes and sub-workflow errors lose data in ways this does not show.

Run it →

 05

The account stopped sending and the pipeline kept moving

A GoHighLevel sub-account crosses its bounce threshold partway through a 500-contact send, so email is suspended for the whole sub-account. Every other feature keeps running, the pipeline reports 500 onboarded, and 199 of them were never emailed at all.

Proves
Wiring a bounce trigger tells you about the 25 that bounced and cannot name one of the 199 that were missed. GoHighLevel's own documentation says there is no direct way to find them.
Does not
It is a model of documented behaviour, not GoHighLevel. The list is invented, and the tiered minimum send count added in August 2026 is not modelled because the tiers are not published.

The study

Not a demo. Original research, published with the dataset so you can check it.

06

I scanned 1,999 published n8n templates

36,234 nodes, 5,665 findings. 78% make network calls with no retry and no error branch, so when one fails nothing tells you. 129 of the 1,999 were clean.

Proves
The workflows most people start from are demonstrations, and nothing on the canvas tells you the difference.
Does not
Static analysis only. It never ran a workflow, so it cannot see wrong logic, a changed API contract, or an invalid credential.

Read it, and run recount.py against the raw data →

 07

n8n Doctor, the scanner behind the 78%

The study published its numbers but not the rules that produced them. This is the scanner itself, in Python and in JavaScript, with a differential test that compares every field of every finding across 91 files and finds zero disagreements. Paste your own workflow and it runs in your browser.

Proves
The 78% came from rules you can read, and the browser version does not quietly differ from the one that ran the scan. Twelve deliberate sabotages of the port were fired at that test and it caught eleven. The one it missed is published on the page, with the two fixtures that close it.
Does not
It cannot regenerate the 78% from scratch. The 1,999 workflow bodies were not kept and api.n8n.io disallows re-fetching them, so only the arithmetic and the rules can be checked today.

How these are built

The rules are the point. Anything else is a screenshot.

  • 01

    It has to run, not describe. A screenshot proves nothing and a case study proves less. If you cannot try it, it is not on this page.

  • 02

    One claim per bench. Each page proves a single specific failure and its fix. Nothing here is a general security product or a scanner.

  • 03

    The limits are published. Every bench has a section saying what it does not catch, written before anyone asked.

  • 04

    The code on the page is the code that ran. Each bench prints its control function from that function's own source, so what you read cannot drift from what just executed.

  • 05

    Where a bench cites the outside world, every line carries its source. Bench 02 also ships a script that checks each quotation against the sources' raw HTML and fails if one has drifted.
